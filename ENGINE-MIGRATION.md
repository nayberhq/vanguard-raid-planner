## Implementation

- `public/allocation.js`: shared eligibility queries and exclusion reasons; per-job option index; compiled role/presence model; role matching supply bounds; all-run constrained drafting; repeated-character fallback; bounded large-neighbourhood reassignment; separate validation and objective.
- Existing allocator retained as a quick incumbent generator. Its legacy objective cannot accept the final result: global allocation policy compares incumbents and complete drafts.
- Policy: hard validity; Primary first assignments; other first assignments; locked instance count and severity; Primary extras; other extras; worst-raid preferred deficits, total preferred staffing/role priority, soft constraints, experience and class preferences; class variety and fairness.
- The two old mode values remain import-compatible. They now select whether player class preferences or experience balance comes first among finishing objectives. Neither alters the higher participation/hard-validity policy.
- Primary extras are absolute: fourth Primary run beats a second non-Primary run when first-run coverage, hard validity and lock goals tie.
- Recommendation comparisons share participation/lock/Primary priorities, but do not add teams solely to increase non-Primary extras. Invalid drafts cannot be offered as valid recommended configurations.
- Old `kinsman` flags migrate to `primary`, which is the exported canonical property. The old helper name remains as a compatibility alias. UI says Primary.
- Fellowship balancing permits identical class/spec/role swaps if experience differs. Tentative alternatives reject inexperienced repeats and consult shared eligibility.
- All budgets run inside the existing worker, retaining cancellation/watchdogs and incumbent results. Small fixture tests compare against exhaustive enumeration; a realistic quick-search fixture checks runtime bounds.

## Limits and follow-up work

This implements the browser-native hybrid backend, not an external CP-SAT dependency or a proof of optimality. Constraint evaluations for complex fellowship placement and cooldown coverage retain the existing bounded evaluators. Hard-check failures mean no valid solution was found by those checks/search; they do not prove infeasibility. Partial results remain clearly marked. The fallback incumbent for incomplete schedules is still generated by the legacy allocator.

Before retiring the seed allocator or claiming optimality, benchmark real problem sessions against an independent exact solver. Separate feasibility, participation, lock count, worst-raid quality and runtime in that benchmark. Do not silently relax hard requirements or infer that timed-out searches establish necessity of repeats.
